# Postgres cho bản host, giữ lớp Repo và SQL tay (không ORM)

- **Ngày:** 2026-11-14 · **Ai quyết:** PO chốt Postgres (4A); AI chọn cách chuyển (tạm chọn)

## Bối cảnh

`db/repo.py` có 2.342 dòng SQL tay, khoá bằng `threading.RLock`, transaction `BEGIN IMMEDIATE`; sổ coin chỉ thêm giữ bằng
trigger SQLite (`0012`, `0013`). Nhiều máy chủ API cần một DB chung ([F50](../features/F50-postgres.md)).

## Lựa chọn

- Một lớp `Repo`, thêm lớp dialect nhỏ (placeholder, thời gian, JSON, `ON CONFLICT`, tìm kiếm); bản tự chạy vẫn SQLite.
- Migration Postgres ở `db/migrations_pg/`, cùng số với SQLite; test kiểm hai thư mục đi song song.
- Sổ coin: trigger PL/pgSQL + thu hồi `UPDATE/DELETE` của vai trò app; ví khoá `FOR UPDATE`; idem bằng `ON CONFLICT`.
- `tsvector('simple')` (giữ dấu) thay FTS5; `pgvector` thay vector BLOB (đổi [khong-sqlite-vec](khong-sqlite-vec.md) chỉ
  cho bản host).
- Chạy toàn bộ pytest trên cả hai backend.
- **Mô hình kết nối** (sửa sau phản biện, [docs/server.md §5.5](../../docs/server.md)): bỏ "một kết nối dùng chung +
  `RLock`"; mỗi đơn vị công việc mượn một kết nối từ pool qua `contextvar`; `coins/*`, `auth/*` nhận kiểu `DbConn` chung
  thay `sqlite3.Connection`; `RETURNING id` thay `lastrowid`; lớp dialect ánh xạ lỗi. Đây là phần việc lớn nhất của F50.
- **Kind/lý do có thể thêm giá trị** (`coin_ledger.kind`, `coin_holds.release_reason`): ở Postgres là bảng tra + khoá
  ngoại (thêm bằng `INSERT`, vẫn "chỉ thêm"). SQLite giữ nguyên `CHECK` vì bản tự chạy không bao giờ ghi các giá trị mới.
- Kiểu dữ liệu: `GENERATED BY DEFAULT AS IDENTITY`, `timestamptz(3)`, `handle citext`, `coin_day date` (dialect trả
  `str`). PgBouncer chế độ transaction: `prepare_threshold=None`; migration và LISTEN nối thẳng Postgres.

## Vì sao

Viết lại bằng ORM là rủi ro lớn nhất có thể tránh: mọi hàm `Repo` đã có test, giữ SQL thì test cũ chứng minh bản Postgres.

## Đã cân nhắc

SQLAlchemy ORM / SQLModel (viết lại hết); giữ SQLite với LiteFS/rqlite (một nơi ghi, hệ sinh thái nhỏ); MySQL (thiếu
`pgvector`, trigger yếu hơn).
